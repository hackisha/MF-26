# Keep Benchmark Artifacts Ignored

## Context

The MF Log Analyzer v2 foundation benchmark generated a `synthetic_300k.csv` file in the project root. The benchmark passed, but the run left a large untracked file in `git status`, creating a risk that a generated dataset could be accidentally committed or obscure real changes.

## Guidance

Benchmark scripts should write generated files into a narrow artifact directory that is ignored by git. Add a specific ignore rule for that directory rather than a broad `*.csv` rule, because sample CSV fixtures may be useful source files.

For one-off legacy generated paths, add a narrow ignore rule or delete the file before finishing the branch.

## Why This Matters

Benchmarks are useful only if they are easy to run repeatedly. If each run dirties the worktree, developers either stop running the benchmark or learn to ignore `git status`, both of which make releases less safe.

## When to Apply

Use this pattern when a benchmark, demo, export, report, or fixture generator creates:

- Large files.
- Files outside the temporary directory.
- Files that are regenerated by normal verification commands.

## Example

```text
mf-log-analyzer-v2/benchmarks/artifacts/
mf-log-analyzer-v2/synthetic_300k.csv
```

The first rule is the intended artifact directory. The second is a narrow legacy guard for the old output path.
