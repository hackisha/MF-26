# Elec App 설계 문서

작성일: 2026-05-21

## 목표

MF-26 engine/elec 팀을 위한 오프라인 우선 배선 디버깅 앱을 만든다. 이 앱은 EasyEDA 회로도 JSON export를 분석해서 부품을 분류하고, ECU 핀에서 커넥터를 거쳐 센서/액추에이터까지 이어지는 배선을 추적하며, 현장 디버깅에 필요한 자료를 한 프로젝트 안에 모아두는 것을 목표로 한다.

첫 버전은 정적 웹앱/PWA로 만든다. 백엔드 서버 없이 브라우저에서 실행되어야 하며, 차고나 대회장처럼 인터넷이 불안정한 환경에서도 사용할 수 있어야 한다.

## 주요 사용자

- 차량 옆에서 배선을 디버깅하는 engine/elec 팀원
- 업데이트된 회로 설계를 리뷰하는 팀원
- 커넥터 pinout, 메모, 데이터시트, 대회 규정을 한곳에서 확인해야 하는 후임 팀원

## 프로젝트 흐름

앱은 매번 JSON을 업로드해서 보는 도구가 아니라, 저장된 프로젝트를 열어 쓰는 도구다.

1. 사용자가 Elec App 프로젝트를 새로 만들거나 연다.
2. 사용자가 EasyEDA JSON 회로도 export를 업로드한다.
3. 앱이 회로도를 파싱하고 정규화된 연결 모델을 만든다.
4. 앱이 가능한 부품은 자동으로 분류한다.
5. 앱이 애매한 부품을 업로드 직후 분류 확인 큐에 보여준다.
6. 사용자가 부품 역할, 별칭, 데이터시트, 메모, 주요 정보를 확정한다.
7. 앱이 프로젝트를 로컬에 저장한다.
8. 이후 사용자는 JSON을 다시 업로드하지 않고 저장된 프로젝트에서 디버깅 화면을 사용한다.
9. 회로도가 바뀌면 새 EasyEDA JSON을 업로드한다.
10. 앱이 새 회로도와 기존 프로젝트를 비교하고, 바뀌었거나 애매한 항목만 다시 확인한다.

## 플랫폼 방향

MVP는 정적 웹앱/PWA로 만든다.

- 브라우저에서 백엔드 없이 실행한다.
- 최근 프로젝트 데이터를 로컬에 저장한다.
- 프로젝트 파일 가져오기/내보내기를 지원한다.
- 나중에 네이티브 파일 접근이나 Windows 앱 배포가 중요해지면 Tauri로 감쌀 수 있게 한다.

핵심 디버깅 기능은 인터넷 연결에 의존하지 않아야 한다.

## 입력 데이터

현재 샘플 파일:

`SCH_26.5.11-배선도_2026-05-19.json`

샘플에서 확인한 EasyEDA 구조:

- 최상위 key는 `editorVersion`, `docType`, `title`, `description`, `colors`, `schematics` 등을 포함한다.
- 회로 데이터는 `schematics[].dataStr.shape[]`에 들어 있다.
- 샘플의 shape 개수는 1275개다.
- 확인된 shape type 개수는 `LIB: 39`, `W: 324`, `N: 464`, `J: 89`, `T: 248`, `F: 9`다.
- 확인된 부품 예시는 `EMU_BLACK_SYMBOL`, `EMU_GRAY_SYMBOL`, `MOLEX_12PIN`, `HDR-F-2.54_1X2`, `HDR-F-2.54_1X3`, 릴레이, 다이오드 등이다.

파서는 실제 샘플에서 확인한 EasyEDA 필드를 기준으로 구현한다. 지원하지 않는 shape 문자열이 있어도 전체 import를 실패시키지 않고 경고로 처리해야 한다.

## 핵심 모듈

### Import / Parser

EasyEDA JSON을 읽고 다음 정보를 추출한다.

- 원본 파일 메타데이터
- `LIB` shape 문자열에서 부품 정보
- `LIB` 내부의 `P` segment에서 부품 핀 정보
- 관련 `T`, `F`, net label 구조에서 텍스트와 라벨 정보
- `W`, `J` 등에서 와이어, 접점, 도형 기반 연결 정보

파서는 나머지 앱에서 쓰기 쉬운 정규화 데이터를 출력한다. 애매한 결과를 UI에서 설명할 수 있도록 원본 shape 참조도 보존한다.

### Connectivity Engine

핀, 와이어 끝점, 접점, net label을 기반으로 연결 그래프를 만든다.

역할:

- 좌표를 기준으로 핀과 와이어 geometry를 연결한다.
- 접점과 공유 끝점을 통해 와이어끼리 연결한다.
- 신뢰할 수 있는 경우 net label을 그래프 node와 연결한다.
- ECU 핀에서 커넥터 핀을 거쳐 센서/액추에이터 부품까지 추적한다.
- 애매한 연결은 확정 연결로 처리하지 않고 "확인 필요"로 표시한다.

### Classification Flow

분류는 하이브리드 방식으로 한다.

자동 추정:

- `EMU_*` 부품은 ECU 후보로 본다.
- `MOLEX_*`, `HDR-*` 부품은 커넥터 후보로 본다.
- 부품 이름, package 이름, 핀 수, 주변 텍스트 라벨을 이용해 confidence를 보정한다.

사용자 확인:

- 애매한 부품은 import 직후 분류 확인 큐에 표시한다.
- 사용자는 각 항목을 ECU, 커넥터, 센서, 액추에이터, 전원 부품, 기타 중 하나로 지정할 수 있다.
- 사용자는 `ECU Gray`, `Main Connector`, `Fuel Pump` 같은 별칭을 붙일 수 있다.
- 앱은 애매한 항목을 조용히 추측하지 않고 사용자에게 물어본다.

### Project Store

앱 내부 로컬 저장과 프로젝트 파일 가져오기/내보내기를 모두 지원한다.

프로젝트에 저장되는 정보:

- 현재 회로도 메타데이터와 hash
- 정규화된 부품, 핀, 연결 그래프
- 사용자 분류와 별칭
- 데이터시트 링크와 첨부 파일 참조
- 전체 배선도 첨부
- 대회 규정 첨부와 링크
- 부품/핀 메모
- 측정 체크리스트와 측정 기록
- 회로도 업데이트 매칭 기록

프로젝트 JSON export는 사용자가 만든 메타데이터와 첨부 파일 참조를 보존한다. MVP에서는 첨부 binary 파일을 브라우저 저장소에 저장해서 로컬 오프라인 열람을 지원하되, 일반 JSON export에는 binary 파일을 직접 포함하지 않는다. 나중에 프로젝트 데이터와 binary 파일을 함께 묶는 bundle export 형식을 추가할 수 있다.

### Update Matcher

새 EasyEDA JSON이 업로드되면 저장된 프로젝트와 비교한다.

매칭 순서:

1. EasyEDA/internal ID가 유지된 경우 ID 기준으로 매칭
2. 심볼/package 이름
3. 핀 수와 핀 배열
4. 좌표 근접도
5. 주변 라벨과 연결된 net 구조

결과 처리:

- confidence가 높은 match는 기존 분류, 별칭, 메모, 첨부를 유지한다.
- confidence가 낮은 match는 review queue에 넣는다.
- 새 부품은 추가됨으로 표시한다.
- 사라진 부품은 삭제됨으로 표시한다.
- 핀 연결이 바뀐 항목은 업데이트 요약 화면에 보여준다.

## 주요 UI

### 프로젝트 홈

마지막으로 열었던 프로젝트와 주요 작업을 보여준다.

- 최근 프로젝트 열기
- EasyEDA JSON import
- Elec App 프로젝트 import
- Elec App 프로젝트 export
- 배선 디버거 열기

### 업로드 / 분석 화면

JSON 업로드 후 parse 요약을 보여준다.

- 부품 개수
- 와이어 개수
- 접점 개수
- net label 개수
- 지원하지 않거나 애매한 shape 개수
- 감지된 ECU, 커넥터, 센서, 액추에이터, 기타 후보

### 분류 확인 큐

업로드나 업데이트 직후 애매한 부품을 보여준다.

각 부품에 표시할 정보:

- 원본 symbol/package 이름
- 핀 수
- 좌표 또는 sheet 참조
- 주변 텍스트 라벨
- 추천 분류와 confidence
- 사용자 분류 선택 UI
- 별칭 입력란

### 검색 디버거

현장 디버깅의 주 화면이다.

검색 대상:

- 원본 부품명
- 사용자 별칭
- `ECU Gray pin 12` 같은 핀 참조
- `+12V`, `GND`, signal name 같은 net label
- `연료펌프` 같은 한국어 별칭

결과에 표시할 정보:

- 검색된 부품 또는 핀
- 연결 경로: ECU 핀 -> 커넥터 핀 -> 센서/액추에이터
- 같은 net에 연결된 다른 지점
- 애매한 연결 경고
- 선택한 핀/부품의 메모와 측정 체크리스트
- 선택한 부품의 데이터시트 링크와 첨부

### 커넥터 Pinout 표

커넥터 하나를 선택해서 핀별 정보를 보여준다.

열 구성:

- 핀 번호
- net 또는 signal label
- 연결된 ECU 핀
- 대상 부품
- 대상 핀
- 메모
- 예상 측정값
- 마지막 실측값과 상태

표는 빠르게 훑어볼 수 있어야 하며, 멀티미터로 현장 디버깅할 때 바로 쓸 수 있어야 한다.

### 부품 정보 패널

관련 화면에서 부품에 hover 또는 click했을 때 표시된다.

표시할 정보:

- 별칭과 EasyEDA 원본 이름
- 분류
- 핀 수
- 연결된 net과 대상
- 데이터시트 링크
- 첨부된 데이터시트 파일
- 부품 메모
- 관련 측정 기록

click하면 고정된 side panel을 열고, hover는 간단한 preview를 보여준다.

### 전체 배선도 탭

업로드된 전체 배선도 이미지나 PDF를 저장하고 보여준다.

MVP 동작:

- 업로드한 배선도 파일 보기
- 확대/축소
- 이동
- 프로젝트와 파일 연결 유지

추후 동작:

- ECU, 커넥터, 센서, 액추에이터 위치 marker 추가
- marker와 부품 연결
- 검색 결과나 커넥터 행에서 배선도 marker로 이동

### 대회 규정 탭

대회 규정 링크와 첨부 파일을 저장한다.

MVP 동작:

- 링크 추가
- PDF나 문서 첨부
- 첨부 파일 오프라인 열람
- 중요한 규정 section에 대한 메모 추가

### 메모와 측정 기록

부품/핀 메모:

- 모든 부품 또는 핀에 자유 텍스트 메모를 남길 수 있다.
- 알려진 취약 지점, 수리 이력, 배선 routing 정보, 인수인계 내용을 기록하는 데 사용한다.

측정 체크리스트:

- 예상값
- 측정 조건
- 실제 측정값
- 정상/비정상/미확인 상태
- 측정 시각과 선택 메모

## 에러 처리

- 잘못된 JSON: 명확한 오류 메시지를 표시하고 현재 프로젝트를 변경하지 않는다.
- 지원하지 않는 EasyEDA 구조: `schematics[].dataStr.shape[]` 같은 필수 경로가 없음을 표시한다.
- 부분 parse 실패: 지원 가능한 shape는 계속 처리하고 실패한 shape 개수를 보여준다.
- 애매한 연결: "확인 필요"로 표시하고 확정 trace에는 넣지 않는다.
- 애매한 분류: 분류 확인 큐로 보낸다.
- 업데이트 매칭 충돌: 사용자에게 기존 부품 후보 중 올바른 항목을 고르게 하거나 새 부품으로 표시하게 한다.
- 로컬 저장 실패: 프로젝트 export를 안내하고 자동 로컬 저장이 동작하지 않을 수 있음을 경고한다.
- 첨부 파일 누락: 메타데이터는 유지하고 "파일 다시 연결 필요"로 표시한다.
- 오프라인 모드: 핵심 프로젝트 화면은 계속 동작해야 하며, 외부 링크는 사용할 수 없을 수 있음을 표시한다.

## 테스트 / 검증 기준

Parser 테스트:

- 현재 EasyEDA 샘플을 crash 없이 parse한다.
- 부품, 와이어, 접점, 라벨 개수를 안정적으로 추출한다.
- `EMU_*`, `MOLEX_12PIN`, `HDR-*` 같은 대표 부품의 핀과 좌표를 추출한다.

Connectivity 테스트:

- 핀, 와이어, 접점으로 graph node를 만든다.
- fixture로 정한 경로에서 ECU 핀 -> 커넥터 핀 -> 대상 부품 trace가 나온다.
- 좌표나 net label이 애매한 경우 review-needed로 표시한다.

Classification 테스트:

- confidence가 높은 `EMU_*`를 ECU 후보로 분류한다.
- `MOLEX_*`, `HDR-*`를 적절한 confidence의 커넥터 후보로 분류한다.
- confidence가 낮은 부품을 분류 확인 큐로 보낸다.
- 사용자가 지정한 분류와 별칭이 새로고침/import/export 후에도 유지된다.

Update 테스트:

- ID가 일치하면 기존 메타데이터를 유지한다.
- ID가 바뀐 경우 symbol/package/pin/coordinate 기반 fallback matching을 수행한다.
- 추가, 삭제, 변경된 부품을 표시한다.
- confidence가 낮은 match에서는 사용자 분류를 조용히 덮어쓰지 않는다.

UI 테스트:

- 원본 이름, 별칭, 핀, net label, 한국어 별칭으로 검색된다.
- 커넥터 pinout 표가 ECU, 대상, 메모, 측정 기록을 표시한다.
- 부품 정보 패널이 데이터시트 링크와 메모를 표시한다.
- 전체 배선도 탭과 대회 규정 탭이 첨부 파일 또는 저장된 참조를 연다.
- 핵심 앱 기능이 오프라인에서도 동작한다.

Project persistence 테스트:

- 로컬 저장소에서 마지막 프로젝트를 복원한다.
- export/import가 분류, 별칭, 메모, 측정 기록, 첨부 메타데이터를 보존한다.
- 저장 실패가 활성 프로젝트를 손상시키지 않는다.

## MVP 범위

MVP에 포함:

- 정적 웹앱/PWA shell
- EasyEDA JSON import
- 현재 샘플 구조를 기준으로 한 parser
- 부품/핀/와이어/접점/net label 정규화
- 연결 graph와 path tracing
- 하이브리드 부품 분류
- 업로드 직후 분류 확인 큐
- 프로젝트 로컬 저장
- 프로젝트 파일 export/import
- 검색 디버거
- 커넥터 pinout 표
- 부품 hover/click 정보 패널
- 데이터시트 링크와 첨부 메타데이터
- 전체 배선도 탭과 이미지/PDF 보기
- 대회 규정 탭과 링크/파일 관리
- 부품/핀 메모
- 측정 체크리스트와 측정 기록

MVP에서 제외:

- 전체 배선도 이미지 위 marker 편집
- 검색 결과에서 배선도 marker로 이동
- 첨부 binary 파일까지 포함하는 프로젝트 bundle archive
- Tauri 데스크톱 패키징
- 다중 사용자 협업
- cloud sync

## 구현 메모

- 첫 구현은 시각적 완성도보다 parser와 trace 결과의 정확성을 우선한다.
- 앱은 애매한 parser 판단에 대해 원본 근거를 보여줄 수 있어야 한다.
- UI는 마케팅용 랜딩 페이지처럼 만들지 않고, 현장에서 빠르게 읽고 조작할 수 있는 조밀하고 실용적인 화면으로 만든다.
- parser, graph logic, storage, UI component를 분리해서 EasyEDA 형식 변화가 생겨도 전체 앱을 다시 작성하지 않게 한다.
