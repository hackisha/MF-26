# EMU 로그 재생 및 분석 탭 설계 문서

작성일: 2026-05-22

## 목표

EMU-LOGGER로 기록한 CSV 로그를 Elec App 안에서 업로드하고, 주행 당시 차량 상태를 시간축에 맞춰 재생하며 분석할 수 있는 탭을 만든다.

이 기능은 실시간 로깅 서버를 대체하는 것이 아니라, 이미 기록된 `.csv` 파일을 다시 열어 문제 지점과 센서 상관관계를 빠르게 찾는 오프라인 분석 도구다.

## 참고한 EMU-LOGGER 구조

분석한 프로젝트: `hackisha/EMU-LOGGER`

주요 구조:

- Raspberry Pi 쪽 코드가 CAN, GPS, 가속도 데이터를 모아 CSV로 저장한다.
- Flask/Socket.IO 기반 web UI는 `telemetry_update` 이벤트로 들어오는 현재 프레임 데이터를 표시한다.
- 원본 web UI는 대략 `dashboard`, `sensor`, `gps`, `accel` 화면으로 나뉜다.
- CSV 주요 컬럼은 `Timestamp`, `RPM`, `VSS_kmh`, `Gear`, `TPS_percent`, `CLT_C`, `OilTemp_C`, `OilPressure_bar`, `FuelPressure_bar`, `Batt_V`, `CEL_Error`, `Latitude`, `Longitude`, `GPS_Speed_KPH`, `ax_g`, `ay_g`, `az_g` 등이다.
- DRS 계열 코드에는 `ADU_ax_g`, `ADU_ay_g`, `ADU_az_g` 같은 추가 가속도 컬럼이 있을 수 있다.

## UX 방향

선택한 방향은 하이브리드 재생 + 분석 방식이다.

상단에는 EMU-LOGGER의 대시보드 느낌을 살려 현재 재생 프레임의 핵심 센서값을 카드로 보여준다. 하단에는 로그 전체를 분석하는 그래프, GPS 경로, G-G 다이어그램, 이벤트 타임라인을 배치한다.

사용자는 이 탭에서 다음 흐름으로 작업한다.

1. 로그 재생 탭을 연다.
2. EMU-LOGGER CSV 파일을 업로드한다.
3. 앱이 CSV 컬럼, 샘플 수, 기록 시간, 추정 샘플링 주기를 요약한다.
4. 사용자가 주요 센서 카드를 고른다.
5. 사용자가 오버레이 그래프에 올릴 센서를 최대 4개까지 고른다.
6. play/pause, 배속, scrubber로 로그를 재생한다.
7. 현재 재생 시간에 맞춰 카드, 그래프 세로선, GPS 현재 위치, G-G 현재 점, 이벤트 강조가 함께 움직인다.
8. 이상 이벤트를 누르면 해당 시점으로 이동한다.

## 화면 구성

### CSV 업로드 및 세션 요약

CSV를 업로드하면 다음 정보를 보여준다.

- 파일명
- 행 수
- 시작 시간과 종료 시간
- 전체 길이
- 추정 샘플링 주기
- 인식된 센서 컬럼
- 누락된 권장 컬럼

CSV가 EMU-LOGGER 계열 컬럼을 일부만 포함해도 동작해야 한다. 없는 컬럼을 쓰는 시각화는 숨기거나 비활성화한다.

### 주요 센서 카드

사용자가 선택한 주요 센서를 카드 형태로 보여준다.

초기 추천 카드:

- `RPM`
- `VSS_kmh`
- `Gear`
- `TPS_percent`
- `CLT_C`
- `OilTemp_C`
- `OilPressure_bar`
- `FuelPressure_bar`
- `Batt_V`
- `CEL_Error`

카드는 CSV에 실제로 존재하는 숫자 또는 상태 컬럼만 선택 가능하다.

카드 표시 내용:

- 센서명
- 현재 재생 시점의 값
- 단위
- 이전 프레임 대비 변화량
- 경고 상태가 있으면 색상 또는 아이콘

기본 카드는 앱이 자동 추천하고, 사용자가 바꿀 수 있게 한다.

### 센서 4개 오버레이 그래프

CSV에 있는 숫자 센서 컬럼 중 최대 4개를 선택해서 하나의 그래프에 겹쳐 표시한다.

필수 동작:

- 최대 4개 선택 제한
- 선택된 센서별 색상 고정
- 단위가 달라도 한 화면에서 비교할 수 있도록 기본은 정규화 보기
- 툴팁에는 정규화 값이 아니라 실제 원값 표시
- 원값 축 보기 모드는 추후 확장 가능
- 현재 재생 시간은 반투명 세로 playhead로 표시
- 그래프를 클릭하거나 드래그하면 해당 시간으로 이동

대표 사용 예:

- `RPM`, `TPS_percent`, `VSS_kmh`, `CLT_C`를 겹쳐 스로틀 입력과 차량 반응 확인
- `RPM`, `OilPressure_bar`, `FuelPressure_bar`, `TPS_percent`를 겹쳐 고부하 구간 압력 저하 확인
- `Batt_V`, `CEL_Error`, `RPM`, `VSS_kmh`를 겹쳐 전압 드롭과 오류 발생 시점 확인

### 재생바 및 타임라인

로그 전체의 시간축을 제어하는 영역이다.

필수 동작:

- play / pause
- 처음으로 이동
- 이전/다음 이벤트로 이동
- 현재 시간
- 전체 로그 길이
- 재생 속도: `0.25x`, `0.5x`, `1x`, `2x`, `4x`
- scrubber
- 이벤트 마커 표시

재생바의 현재 위치와 그래프의 playhead는 같은 재생 시간을 공유한다.

### GPS 경로

`Latitude`와 `Longitude`가 있으면 GPS 경로를 그린다.

필수 동작:

- 전체 경로 표시
- 현재 재생 위치 마커 표시
- 현재 속도 표시
- 경로 색상은 기본적으로 속도 기준
- GPS 데이터가 없으면 이 패널은 숨김 또는 "GPS 컬럼 없음" 상태로 표시

추후 확장:

- 사용자가 경로 색상 기준을 `GPS_Speed_KPH`, `TPS_percent`, `CLT_C` 등으로 변경
- 랩/섹터 분석
- 출발선 기준 랩 자동 분리

### G-G 다이어그램

`ax_g`와 `ay_g`가 있으면 G-G 다이어그램을 그린다.

필수 동작:

- 전체 로그의 가속도 분포 표시
- 현재 재생 시점의 점 강조
- x축은 lateral 또는 `ay_g`, y축은 longitudinal 또는 `ax_g`
- 최대 좌우/가속/제동 G 요약 표시
- 가속도 컬럼이 없으면 이 패널은 숨김 또는 "가속도 컬럼 없음" 상태로 표시

컬럼 우선순위:

1. `ax_g`, `ay_g`
2. 없으면 `ADU_ax_g`, `ADU_ay_g`

### 이벤트 및 이상값 스트립

로그에서 확인이 필요한 지점을 자동으로 이벤트로 추출하고 타임라인에 표시한다.

1차 이벤트 후보:

- `CEL_Error`가 0이 아닌 시점
- `Batt_V`가 기준 이하로 떨어지는 시점
- `OilPressure_bar`가 기준 이하로 떨어지는 시점
- `FuelPressure_bar`가 기준 이하로 떨어지는 시점
- `CLT_C` 또는 `OilTemp_C`가 기준 이상으로 올라가는 시점
- GPS 좌표가 끊기거나 튀는 시점
- RPM 급변 또는 비정상적으로 0이 되는 시점

기준값은 처음에는 보수적인 기본값을 사용하고, 나중에 팀 설정으로 조정 가능하게 한다.

이벤트를 클릭하면 재생 위치가 해당 시점으로 이동한다.

## 데이터 처리

### CSV 파싱

브라우저에서 CSV 파일을 읽고 파싱한다. 파싱 결과는 다음 형태의 도메인 모델로 변환한다.

- `LogSession`: 파일명, 컬럼 목록, 샘플 목록, 시간 범위, 요약 정보
- `LogSample`: 한 행의 시간, 원본 행 번호, 센서 값 map
- `SensorDefinition`: 컬럼명, 표시명, 단위, 타입, 권장 여부
- `LogEvent`: 이벤트 타입, 시간, 심각도, 설명, 관련 센서값

### 시간축

`Timestamp` 컬럼을 우선 사용한다.

허용 형식:

- ISO 날짜/시간 문자열
- 숫자 epoch
- 초 단위 상대 시간

`Timestamp`가 없거나 해석 불가능하면 행 번호와 추정 샘플링 주기로 상대 시간을 만든다.

### 컬럼 매핑

EMU-LOGGER의 알려진 컬럼은 표시명과 단위를 매핑한다.

예:

- `RPM`: `RPM`
- `VSS_kmh`: `km/h`
- `GPS_Speed_KPH`: `km/h`
- `TPS_percent`: `%`
- `CLT_C`: `C`
- `OilTemp_C`: `C`
- `OilPressure_bar`: `bar`
- `FuelPressure_bar`: `bar`
- `Batt_V`: `V`
- `ax_g`, `ay_g`, `az_g`: `g`

알 수 없는 숫자 컬럼도 선택 가능하게 하되 단위는 비워 둔다.

## 오류 처리

- CSV 파일이 아니면 업로드를 거부한다.
- 헤더가 없으면 "헤더 행이 필요함"을 표시한다.
- 숫자로 해석할 수 없는 값은 빈 값으로 처리하고 해당 컬럼의 invalid count를 요약에 표시한다.
- 샘플 수가 너무 크면 처음에는 전체를 파싱하되, 그래프 렌더링은 다운샘플링한다.
- 필수 시각화 컬럼이 없으면 전체 탭을 실패시키지 않고 해당 패널만 비활성화한다.

## 테스트 기준

도메인 테스트:

- EMU-LOGGER CSV 헤더를 인식한다.
- 숫자, 빈 값, 잘못된 값을 안정적으로 파싱한다.
- `Timestamp`를 상대 시간으로 변환한다.
- 센서 단위를 매핑한다.
- 오버레이 선택은 최대 4개로 제한한다.
- playhead 시간으로 가장 가까운 샘플을 찾는다.
- 이벤트 추출기가 CEL, 전압 드롭, 온도 초과, 압력 저하 이벤트를 만든다.

UI 테스트:

- CSV 업로드 후 세션 요약이 표시된다.
- 주요 센서 카드가 현재 재생 위치에 따라 바뀐다.
- 오버레이 그래프에 선택한 센서가 표시된다.
- 재생바를 움직이면 그래프 playhead와 카드 값이 바뀐다.
- GPS 컬럼이 없으면 GPS 패널이 비활성화된다.
- 가속도 컬럼이 없으면 G-G 패널이 비활성화된다.

수동 검증:

- 실제 EMU-LOGGER CSV 샘플로 업로드, 재생, 센서 선택, 이벤트 이동을 확인한다.
- 데스크톱과 모바일 폭에서 텍스트와 그래프가 겹치지 않는지 확인한다.

## MVP 범위

MVP에 포함:

- 로그 재생 탭
- CSV 업로드
- 세션 요약
- 주요 센서 카드
- 최대 4개 센서 오버레이 그래프
- play/pause, scrubber, 배속
- 그래프 playhead
- GPS 경로 패널
- G-G 다이어그램
- 이벤트 및 이상값 스트립

MVP에서 제외:

- 서버 연동 또는 실시간 Socket.IO 재생
- EMU-LOGGER 원본 UI 전체 복제
- 랩 자동 분리
- 출발선 설정
- 복수 CSV 비교
- 사용자별 클라우드 저장
- 고급 튜닝용 산점도 매트릭스

## 추가로 필요한 정보

정확도를 높이려면 실제 EMU-LOGGER CSV 샘플이 필요하다.

확인하고 싶은 것:

- 실제 `Timestamp` 형식
- 로그 파일 크기와 평균 행 수
- 자주 쓰는 로깅 코드가 `main.py` 계열인지 DRS 계열인지
- 팀에서 위험 기준으로 볼 전압, 수온, 유온, 유압, 연압 기준값
- GPS와 가속도 데이터가 매 로그에 항상 들어가는지
